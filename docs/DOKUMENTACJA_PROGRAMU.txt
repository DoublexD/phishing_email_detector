================================================================================
1. CEL I OPIS SYSTEMU
================================================================================

Email Spoofing Detector to system wykrywania spoofingu i phishingu w
wiadomosciach e-mail. Laczy podejscie regolowe (weryfikacja SPF, DKIM, DMARC,
analiza naglowkow) z uczeniem maszynowym (Random Forest + Isolation Forest).

System oferuje:
- Analiza pojedynczych wiadomosci e-mail przez REST API
- Weryfikacja autentykacji nadawcy (SPF, DKIM, DMARC)
- Analiza naglowkow pod katem anomalii i manipulacji
- Klasyfikacja z wykorzystaniem modeli ML (ensemble)
- Klasyfikacja heurystyczna jako fallback bez wytrenowanych modeli
- Ciagle monitorowanie skrzynki IMAP
- Panel webowy do zarzadzania alertami i przegladania statystyk
- System alertow z persystencja do plikow JSON
- Wersjonowanie i zarzadzanie modelami ML

Technologie:
- Backend: Python 3.10+, FastAPI, scikit-learn, imbalanced-learn
- Frontend: HTML5, CSS3, JavaScript (vanilla)
- Autentykacja e-mail: pyspf, dkimpy, checkdmarc, dnspython
- Serwer ASGI: Uvicorn

6. MODUL: PARSOWANIE E-MAIL (email_parser)

6.1. EmailParser (src/email_parser/parser.py)
---------------------------------------------
Klasa odpowiedzialna za parsowanie surowych wiadomosci e-mail do ustandaryzowanego
slownika danych.

Metody publiczne:

  parse_raw_email(raw_email: bytes) -> Dict[str, Any]
    Parsuje surowa wiadomosc z formatu bytes.
    Wejscie: surowa wiadomosc e-mail jako bajty
    Wyjscie: slownik z danymi e-maila

  parse_email_string(email_string: str) -> Dict[str, Any]
    Parsuje wiadomosc z formatu string (konwertuje do bytes i wywoluje
    parse_raw_email).

  extract_urls(text: str) -> List[str]
    Ekstrahuje adresy URL z tekstu za pomoca wyrazen regularnych.

  get_all_urls(email_data: Dict) -> List[str]
    Ekstrahuje wszystkie unikalne URL z tresci wiadomosci (plain + html).

Struktura danych wyjsciowych (slownik email_data):
  {
    'headers': dict          - Wszystkie naglowki (klucz -> wartosc)
    'from': dict             - Nadawca {'name': str, 'email': str}
    'to': list               - Odbiorcy [{'name': str, 'email': str}, ...]
    'cc': list               - Kopia
    'bcc': list              - Kopia ukryta
    'subject': str           - Temat wiadomosci
    'date': datetime|None    - Data wyslania
    'message_id': str        - Identyfikator wiadomosci
    'reply_to': dict         - Adres Reply-To {'name': str, 'email': str}
    'return_path': str       - Return-Path (sciezka zwrotna)
    'received': list         - Lista naglowkow Received (sparsowane)
    'body': dict             - Tresc {'plain': str, 'html': str}
    'attachments': list      - Zalaczniki [{'filename', 'content_type', 'size'}]
    'authentication_results': str  - Naglowek Authentication-Results
    'received_spf': str      - Naglowek Received-SPF
    'dkim_signature': str    - Naglowek DKIM-Signature
    'x_mailer': str          - Naglowek X-Mailer
    'mime_version': str      - Wersja MIME
    'content_type': str      - Typ zawartosci
  }

6.2. HeaderAnalyzer (src/email_parser/header_analyzer.py)
---------------------------------------------------------
Analizuje naglowki e-mail pod katem anomalii wskazujacych na spoofing.

Metoda glowna:

  analyze(email_data: Dict) -> Dict[str, Any]
    Przeprowadza pelna analize naglowkow. Zwraca slownik z wynikami.

Struktura wynikow:
  {
    'missing_headers': list      - Brakujace wymagane naglowki
    'received_chain_analysis': dict  - Analiza lancucha Received
    'time_anomalies': dict       - Anomalie czasowe
    'suspicious_patterns': list  - Wykryte podejrzane wzorce
    'from_mismatch': bool        - Niezgodnosc From vs Return-Path
    'reply_to_mismatch': bool    - Niezgodnosc From vs Reply-To
    'hop_count': int             - Liczba hopow (Received)
    'anomaly_score': float       - Wynik anomalii (0.0 - 1.0)
    'anomalies': list            - Lista opisow wykrytych anomalii
  }

Co sprawdza:
  - Brakujace wymagane naglowki: From, Date, Message-ID, Received
  - Zbyt wiele hopow (>10) lub brak hopow
  - Opoznienia miedzy hopami (>3600s) i ujemne delty czasowe
  - Data e-maila w przyszlosci lub starsza niz rok
  - Podejrzane wzorce w X-Mailer (YahooMailClassic, IMO) i User-Agent
    (curl, python, wget)
  - Niezgodnosc domen From/Return-Path (wskaznik fałszowania nadawcy)
  - Niezgodnosc domen From/Reply-To (wskaznik przekierowania odpowiedzi)

Obliczanie anomaly_score (0.0 = brak anomalii, 1.0 = bardzo podejrzane):
  - Brakujacy naglowek:         +0.15 za kazdy
  - Niezgodnosc From/Return-Path: +0.25
  - Niezgodnosc Reply-To:       +0.15
  - Data w przyszlosci:         +0.20
  - Podejrzany wzorzec:         +0.10 za kazdy
  - Zbyt wiele hopow (>10):    +0.15
  - Brak hopow (<1):           +0.20

6.3. IMAPClient (src/email_parser/imap_client.py)
-------------------------------------------------
Klient do laczenia z serwerem IMAP i pobierania wiadomosci e-mail.

Metody publiczne:

  connect() -> bool
    Nawiazuje polaczenie z serwerem IMAP (SSL lub bez).

  disconnect()
    Rozlacza z serwerem.

  fetch_new_emails(mark_as_seen: bool = False) -> List[bytes]
    Pobiera nowe wiadomosci od ostatniego sprawdzenia.
    Przy pierwszym wywolaniu zapamiętuje istniejace UID bez pobierania.
    Kolejne wywolania zwracaja tylko nowe wiadomosci.

  fetch_all_emails(limit: int = None) -> List[bytes]
    Pobiera wszystkie wiadomosci z folderu (z opcjonalnym limitem).

  monitor_continuous(callback, interval=60, max_iterations=None)
    Monitoruje folder w trybie ciaglym z zadanym interwalem.

  get_folder_list() -> List[str]
    Zwraca liste folderow na serwerze.

Obsluguje context manager (with IMAPClient(...) as client:).

7. MODUL: WERYFIKACJA AUTENTYKACJI (authentication)
================================================================================

7.1. SPFChecker (src/authentication/spf_checker.py)
----------------------------------------------------
Sprawdza rekordy SPF (Sender Policy Framework) - weryfikuje, czy serwer
nadawcy jest autoryzowany do wysylania poczty w imieniu domeny.

Metody publiczne:

  check_spf(sender_ip, sender_email, helo_domain=None) -> Dict
    Wykonuje pelne sprawdzenie SPF dla podanego IP i adresu e-mail.
    Wynik: pass, fail, softfail, neutral, none, temperror, permerror

  check_from_email_data(email_data: Dict) -> Dict
    Automatycznie wyciaga IP nadawcy z naglowkow Received i wykonuje
    sprawdzenie SPF.

  get_spf_record(domain: str) -> str|None
    Pobiera rekord SPF (TXT) z DNS dla domeny.

  parse_spf_record(spf_record: str) -> Dict
    Parsuje rekord SPF na mechanizmy, modyfikatory i polityke 'all'.

Wyniki SPF:
  pass     - serwer autoryzowany (weryfikacja pomyslna)
  fail     - serwer NIE autoryzowany (aktywny wskaznik spoofingu!)
  softfail - serwer prawdopodobnie nie autoryzowany (slabszy wskaznik)
  neutral  - domena nie deklaruje polityki
  none     - brak rekordu SPF

7.2. DKIMChecker (src/authentication/dkim_checker.py)
-----------------------------------------------------
Sprawdza podpisy DKIM (DomainKeys Identified Mail) - weryfikuje integralnosc
i autentycznosc wiadomosci za pomoca podpisu kryptograficznego.

Metody publiczne:

  check_dkim(raw_email: bytes) -> Dict
    Weryfikuje podpis DKIM surowej wiadomosci.
    Wynik: pass (valid=True), fail (valid=False), none, temperror

  check_from_email_data(email_data: Dict, raw_email: bytes) -> Dict
    Sprawdza DKIM - jesli wiadomosc nie ma podpisu, zwraca result='none'.

  get_dkim_public_key(selector: str, domain: str) -> str|None
    Pobiera klucz publiczny DKIM z DNS.

7.3. DMARCChecker (src/authentication/dmarc_checker.py)
-------------------------------------------------------
Sprawdza polityki DMARC (Domain-based Message Authentication, Reporting &
Conformance) - okresla, co robic z wiadomosciami, ktore nie przechodza SPF/DKIM.

Metody publiczne:

  check_dmarc(domain: str) -> Dict
    Sprawdza polityke DMARC dla domeny.
    Zwraca: valid, record, policy, subdomain_policy, alignment, reporting

  check_from_email_data(email_data: Dict) -> Dict
    Automatycznie wyciaga domene nadawcy i sprawdza DMARC.

  check_alignment(spf_result, dkim_result, from_domain) -> Dict
    Sprawdza alignment (zgodnosc) SPF i DKIM z wymaganiami DMARC.

  get_policy_action(policy: str) -> str
    Mapuje polityke DMARC na akcje: none->ALLOW, quarantine->QUARANTINE,
    reject->REJECT

Parsowane tagi DMARC:
  p     - glowna polityka (none/quarantine/reject)
  sp    - polityka dla subdomen
  pct   - procent wiadomosci objety polityka
  adkim - alignment DKIM (r=relaxed/s=strict)
  aspf  - alignment SPF
  rua   - adresy raportow agregowanych
  ruf   - adresy raportow forensic

8. MODUL: EKSTRAKCJA CECH (feature_extraction)
================================================================================

FeatureExtractor (src/feature_extraction/extractor.py)
------------------------------------------------------
Przeksztalca dane e-maila i wyniki autentykacji na wektor cech liczbowych
(pd.Series), ktorego uzywa model ML do klasyfikacji.

Metoda glowna:

  extract_features(email_data, spf_result, dkim_result, dmarc_result,
                   header_analysis) -> pd.Series
    Ekstrahuje wszystkie grupy cech i zwraca pd.Series z ~60 cechami.

  extract_batch(email_data_list, **kwargs) -> pd.DataFrame
    Ekstrahuje cechy z wielu wiadomosci naraz.

GRUPY CECH (laczy 60+ cech liczbowych):

  A) Cechy autentykacji (_extract_auth_features) - 13 cech:
     spf_pass, spf_fail, spf_softfail, spf_neutral, spf_none
     dkim_valid, dkim_invalid, dkim_none, dkim_signature_count
     dmarc_policy_none, dmarc_policy_quarantine, dmarc_policy_reject,
     dmarc_exists

  B) Cechy naglowkowe (_extract_header_features) - 7 cech:
     hop_count, missing_headers_count, from_return_path_mismatch,
     from_reply_to_mismatch, has_x_mailer, has_message_id, anomaly_score

  C) Cechy czasowe (_extract_temporal_features) - 7 cech:
     hour_of_day, day_of_week, is_weekend, is_night_time,
     date_in_future, avg_hop_delay, max_hop_delay

  D) Cechy tresci (_extract_content_features) - 8 cech:
     body_length, html_body_present, plain_body_present,
     suspicious_keywords_count, exclamation_count,
     capital_letter_ratio, contains_form, contains_script

  E) Cechy URL (_extract_url_features) - 6 cech:
     url_count, external_url_count, ip_address_url_count,
     shortened_url_count, suspicious_tld_count, url_domain_mismatch

  F) Cechy zalacznikow (_extract_attachment_features) - 5 cech:
     attachment_count, has_executable, has_archive, has_document,
     total_attachment_size

  G) Cechy nadawcy (_extract_sender_features) - 8 cech:
     from_name_length, from_contains_reply, from_contains_noreply,
     from_has_numbers, from_domain_length, to_count, cc_count, bcc_count

  H) Cechy tematu (_extract_subject_features) - 8 cech:
     subject_length, subject_word_count, subject_has_urgent,
     subject_has_re_fw, subject_suspicious_keywords,
     subject_has_special_chars, subject_capital_ratio,
     subject_exclamation_count

  I) Cechy sieciowe (_extract_network_features) - 6 cech:

9.1. EmailClassifier (src/ml_models/predict.py)
-----------------------------------------------
Klasyfikator wiadomosci e-mail wykorzystujacy wytrenowane modele.

Inicjalizacja:
  EmailClassifier(models_dir="models", prefix="")
    Laduje modele z katalogu: Random Forest, Isolation Forest, Scaler,
    nazwy cech, konfiguracje (progi, wagi ensemble).

Metody publiczne:

  predict(features: pd.Series|pd.DataFrame) -> Dict[str, Any]
    Glowna metoda predykcji. Zwraca:
    {
      'is_suspicious': bool   - Czy wiadomosc jest podejrzana
      'confidence': float     - Pewnosc predykcji (0.0-1.0)
      'risk_level': str       - Poziom ryzyka: HIGH/MEDIUM/LOW
      'models': dict          - Wyniki poszczegolnych modeli
      'recommendation': str   - Rekomendacja: QUARANTINE/FLAG/ALLOW
      'explanation': list     - Lista wyjasnen decyzji
    }

  predict_batch(features_batch: pd.DataFrame) -> list
    Predykcja dla wielu wiadomosci.

  get_feature_importance(top_n=20) -> pd.DataFrame|None
    Zwraca top N najwazniejszych cech z modelu Random Forest.

  explain_prediction(features, result) -> list
    Generuje czytelne wyjasnienie decyzji.

Logika agregacji predykcji (_aggregate_predictions):
  - Wagi ensemble: RF=0.75, IF=0.25 (konfigurowalne)
  - Przeliczenie IF score na prawdopodobienstwo: 0.5 - raw_score
  - Laczne prawdopodobienstwo: rf_weight * rf_proba + if_weight * if_proba
  - Porownanie z progiem ensemble (domyslnie 0.5)
  - Poziomy ryzyka: >=0.8 HIGH, >=0.5 MEDIUM, <0.5 LOW

Klasyfikacja heurystyczna (_heuristic_classification):
  Fallback gdy brak wytrenowanych modeli. Oparty na punktacji wskaznikow:
    SPF fail:           +15 pkt
    DKIM invalid:       +15 pkt
    From/Return-Path mismatch: +15 pkt
    Reply-To mismatch:  +10 pkt
    >=3 podejrzane slowa: +20 pkt
    1-2 podejrzane slowa: +10 pkt
    IP w URL:           +15 pkt
    Skrocone URL:       +10 pkt
    Podejrzane TLD:     +10 pkt
    Cyfry w nadawcy:    +5 pkt
    Wiele wykrzyknikow:  +5 pkt
    Duzo wielkich liter: +5 pkt
    Plik wykonywalny:   +20 pkt

    Decyzja: >=60 = HIGH, >=30 = MEDIUM, <30 = LOW (bezpieczne)

9.2. ModelTrainer (src/ml_models/train.py)
------------------------------------------
Klasa do pelnego pipeline'u treningu modeli ML.

Metoda glowna:

  full_training_pipeline(X, y, test_size=0.2, hyperparameter_tuning=False)
    Uruchamia caly proces: przygotowanie danych -> trening -> ewaluacja ->
    zapis modeli i wynikow.

Etapy treningu:

  A) Przygotowanie danych (prepare_data):
     - Podzial train/test (stratified)
     - Opcjonalny podzial kalibracyjny (20% z train)
     - Standaryzacja (StandardScaler)
     - Balansowanie klas przez SMOTE (Synthetic Minority Over-sampling)

  B) Trening Random Forest (train_random_forest):
     Domyslne parametry:
       n_estimators=200, max_depth=20, min_samples_split=5,
       min_samples_leaf=2, max_features='sqrt', class_weight='balanced'
     Z hyperparameter_tuning=True:
       RandomizedSearchCV z SMOTE wewnatrz foldow CV (60 iteracji)
       Siatka: n_estimators, max_depth, min_samples_split/leaf,
       max_features, class_weight, criterion

  C) Trening Isolation Forest (train_isolation_forest):
     - Trenowany na danych BEZ SMOTE (oryginalny rozklad)
     - Contamination liczone automatycznie z proporcji phishingu
     - Proba 5 roznych konfiguracji parametrow
     - Wybor najlepszej wg F1-score

  D) Ewaluacja (evaluate):
     - Optymalny prog decyzyjny RF (metoda precision-recall curve)
     - Metryki: classification_report, confusion_matrix, ROC AUC
     - Wazona ewaluacja ensemble RF+IF
     - Prog ensemble z kalibracji (jesli dostepna)

  E) Zapis (save_models):
     - random_forest_classifier.joblib
     - isolation_forest_anomaly.joblib
     - scaler.joblib
     - feature_names.joblib
     - model_config.joblib (progi, wagi ensemble)
     - evaluation_results.json

Uruchamianie z CLI:
  python src/ml_models/train.py \
    --data data/processed/training_data.csv \
    --target is_phishing \
    --test-size 0.2 \
    --tune  # opcjonalnie: tuning hiperparametrow

13. PIPELINE PRZETWARZANIA E-MAILA
================================================================================

Szczegolowy przeplyw od momentu otrzymania e-maila do decyzji:

  WEJSCIE: Surowa wiadomosc e-mail (string lub base64)
  -------

  KROK 1: Walidacja wejscia (app.py::analyze_email)
  ---------
    - Sprawdzenie rozmiaru (<= 10 MB)
    - Dekodowanie base64 (jesli raw_email)
    - Parsowanie wiadomosci

  KROK 2: Parsowanie (parser.py::parse_raw_email)
  ---------
    -> Wynik: slownik email_data z naglowkami, trescia, zalacznikami

  KROK 3: Analiza naglowkow (header_analyzer.py::analyze)
  ---------
    -> Wynik: anomalie, from_mismatch, reply_to_mismatch, anomaly_score

  KROK 4: Weryfikacja autentykacji (opcjonalna)
  ---------
    4a. SPF: spf_checker.check_from_email_data(email_data)
    4b. DKIM: dkim_checker.check_from_email_data(email_data, raw_bytes)
    4c. DMARC: dmarc_checker.check_from_email_data(email_data)
    -> Wynik: slownik authentication_results z SPF/DKIM/DMARC

  KROK 5: Ekstrakcja cech (extractor.py::extract_features)
  ---------
    Wejscie: email_data + auth results + header analysis
    -> Wynik: pd.Series z ~60 cechami liczbowymi

  KROK 6: Klasyfikacja ML (predict.py::predict)
  ---------
    6a. Dopasowanie kolumn do feature_names
    6b. Skalowanie przez StandardScaler
    6c. Predykcja Random Forest (prawdopodobienstwo phishingu)
    6d. Predykcja Isolation Forest (wynik anomalii)
    6e. Agregacja: RF*0.75 + IF*0.25, porownanie z progiem
    6f. Okreslenie risk_level i rekomendacji
    -> Wynik: is_suspicious, confidence, risk_level

  KROK 7: Reguly nadrzedne (app.py)
  ---------
    Budowa listy wskaznikow spoofingu na podstawie autentykacji i naglowkow.
    Rozroznienie silnych (SPF_FAIL, DKIM_FAIL) od informacyjnych (SPF_NONE).
    Jesli istnieja SILNE wskazniki a model zwrocil is_suspicious=False:
      -> wymuszenie is_suspicious=True, podniesienie risk_level

  KROK 8: Generowanie alertu (app.py)
  ---------
    Jesli is_suspicious=True:
      -> Tworzenie alertu z unikalnym ID (ALERT_xxx)
      -> Zapis do data/alerts.json (w tle, thread-safe)

  KROK 9: Aktualizacja statystyk (app.py::update_statistics)
  ---------
    Inkrementacja total_analyzed i suspicious_detected lub safe_emails.
    Zapis do data/stats.json (thread-safe).

  WYJSCIE: EmailAnalysisResponse
  --------
    is_suspicious, confidence, risk_level, recommendation,
    spoofing_indicators, authentication, header_analysis,
    timestamp, alert_id

  4. W petli co check_interval sekund pobiera nowe wiadomosci
  5. Kazda nowa wiadomosc przechodzi pelny pipeline analizy
     (_process_imap_email)
  6. Jesli wykryto phishing -> generowany jest alert (IMAP_xxx)
  7. POST /api/imap/stop ustawia flage stop, watek konczy prace

Thread-safety:
  - Wspoldielony stan (alerty, statystyki) chroniony przez threading.Lock
  - Watek IMAP jest daemonem (konczy sie z procesem glownym)
  - Petla sprawdza flage stop co 1 sekunde (nie co interwal)

20. OGRANICZENIA I UWAGI
================================================================================

  1. Bez wytrenowanych modeli ML system dziala w trybie heurystycznym.
     Jakosc detekcji zalezy od jakosci zbioru treningowego.

  2. Persystencja oparta na plikach JSON (alerts.json, stats.json) jest
     odpowiednia dla prototypu. Dla produkcji zalecane jest przejscie na
     baze danych (PostgreSQL, Redis).

  3. Weryfikacja SPF/DKIM/DMARC wymaga dostepu do DNS. Zapytania moga
     byc wolne lub niemozliwe w srodowiskach offline.

  4. Limit rozmiaru wiadomosci: 10 MB. Wieksze e-maile sa odrzucane (413).

  5. Monitorowanie IMAP wymaga poprawnej konfiguracji w config.yaml.
     Dla Gmail wymagane jest haslo aplikacji (App Password).

  6. Frontend nie wspiera autentykacji uzytkownikow - jest przeznaczony
     do uzytku w sieciach zaufanych.

  7. CORS jest ograniczony do localhost - nalezy dostosowac dla wdrozenia
     produkcyjnego.

  8. Thread-safety zapewniony przez threading.Lock - jednowatkowe zapisy.
     Przy duzym obciazeniu rozwazyc asynchroniczna baze danych.

  9. Isolation Forest jest trenowany na danych bez SMOTE (zachowuje
     oryginalny rozklad). Contamination jest liczone automatycznie.

 10. Optymalny prog decyzyjny (threshold) jest dobierany na zbiorze
     kalibracyjnym (jesli wystarczajaco duzy). Przy malych zbiorach
     danych uzywany jest domyslny prog 0.5.
